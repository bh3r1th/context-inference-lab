Synthetic fixtures are generated by `scripts/generate_fixtures.py` without external data.
`synthetic/documents/` contains all model-visible sources, including structured city lookup rows.
`events.json` contains dynamic input only; `expected.json` is evaluation-only ground truth.
Rule IDs and source predicates are deliberately explicit for a deterministic compilation baseline.

## Enterprise workload

`enterprise/` is the larger synthetic benchmark. Generate and validate it without a model:

```bash
python -m contextbench.workload --config configs/datasets/small.json --output data/enterprise
python -m contextbench.workload --config configs/datasets/medium.json --output data/enterprise-medium --seed 42
python -m contextbench.workload --validate-only --output data/enterprise
```

Install the project first (`python -m pip install -e .`), or set `PYTHONPATH=src`.
Small/medium/large configs contain 60/600/6000 events, 80/400/1600 reference sections
per document, and 24/120/600 city lookup rows. Every size includes all six case types.
The seed controls claim details and lookup values. Generation uses a local random
generator, fixed effective date, stable ordering, and no external or proprietary data.
Identical config and seed produce byte-identical files. Known output files are overwritten.

- `documents/`: four policy, control, exception, and lookup references. Normative
  `RULE` records have stable IDs, named sections, predicates, and prose. Nonbinding
  archive sections increase context size. The emergency rule occurs near the end
  of the exception document; base and department rules occupy distant policy sections.
- `lookup.json`: machine-readable city limits, also rendered in the lookup document.
- `sources.json`: source ID catalog with exact document and section provenance.
- `events.json`: model-visible input records, without answer annotations.
- `records.json`: full annotated event records. Each declares `required_source_ids`,
  `critical_rules`, its case type, and expected structured output in `ground_truth`.
- `expected.json`: the same ground truth indexed by event ID for the existing evaluator.
- `output.schema.json`: strict structured decision schema.
- `manifest.json`: generator format version, complete configuration, and SHA-256 hashes.

Keep `records.json`, `expected.json`, and their source requirements out of model prompts.
Lookup IDs are source fact IDs and appear alongside policy rule IDs in required sources.
All required sources are treated as critical. Unknown-city abstention cites the completeness
rule rather than a nonexistent lookup ID; table absence is the evidence.

Cases cover ordinary approval, same-document department caps, cross-document vendor
rejection, buried emergency overrides, city-specific boundary comparisons, and abstention
for unknown cities, missing amounts, conflicting receipts, or unsupported emergencies.
The completeness rule takes precedence, followed by emergency limit replacement and
vendor rejection. Boundary variants exercise equality and one dollar above limits.
These are repeated controlled scenario families, not independent samples of real enterprise
behavior. Archive text is intentionally repetitive; document bytes are not token counts.

Validation checks source/document and lookup agreement, complete one-to-one event answers,
strict output schemas, required rule existence and coverage, decision/limit consistency,
annotated record agreement, configured counts, and artifact hashes. Tests also exercise
determinism, corruption rejection, all sizes, boundaries, and precedence. The consistency
oracle is dataset-authoring code only; no inference implementation is added.
